1. OBJETIVO DO PROJETO

A ConectaTech é uma plataforma de capacitação digital, carreira e oportunidades. O protótipo inicial armazenava preferências e progresso no navegador. O projeto foi evoluído para utilizar contas, autenticação e dados reais no Supabase, com implantação na Vercel.

Requisitos solicitados durante o trabalho:
- Utilizar dados reais, sem números fictícios de usuários ou progresso.
- Exibir o progresso do usuário conectado.
- Conectar autenticação, consentimentos, progresso, perfis e oportunidades ao Supabase.
- Permitir login apenas com e-mail e senha.
- Criar perfil pessoal, foto, nome de usuário, biografia, cidade e perfil público/privado.
- Permitir edição parcial do perfil, sem obrigar o preenchimento de todos os campos.
- Criar páginas próprias para as principais seções.
- Modernizar o visual com profundidade, elementos flutuantes, animações e melhor organização.
- Corrigir sobreposição, espaçamento, seleção indevida de textos e responsividade.
- Aplicar redação correta em português do Brasil, com acentuação, concordância e pontuação.
- Criar mini perfil no cabeçalho após o login.
- Criar currículo, portfólio, trilhas, aulas, oportunidades, impacto e administração.
- Registrar todas as mudanças no GitHub para continuidade em outro computador.

7. PROBLEMAS ENCONTRADOS E SOLUÇÕES

- A CLI do Supabase não autenticou por erro de transporte/certificado.
  Solução: migrações executadas pelo SQL Editor do painel.

- Comandos PowerShell foram colados no SQL Editor.
  Solução: usar Get-Content ... | Set-Clipboard somente no terminal e colar no SQL Editor apenas o SQL copiado.

- profiles já existia sem is_public.
  Solução: migração compatível, adicionando apenas colunas ausentes.

- lessons já existia com id UUID e track_id obrigatório.
  Solução: não substituir o modelo antigo; adaptar o site para tracks e lessons.track_id.

- A área de perfil mostrava estados conectado e desconectado ao mesmo tempo.
  Solução: regra .app-page [hidden] com display none.

- O mini perfil oscilava entre páginas.
  Solução: apresentação armazenada localmente e renderizada antes da validação silenciosa da sessão.

- FormData falhava nos formulários de carreira.
  Causa: event.currentTarget era consultado depois de await.
  Solução: preservar a referência do formulário antes da operação assíncrona.

- Currículo e portfólio eram formulários básicos em diálogos.
  Solução: criação de páginas completas e responsivas.

11. COMO CONTINUAR EM CASA SEM PERDER ALTERAÇÕES

Antes de editar:

git status
git branch --show-current
git fetch origin

Se houver alterações antigas ainda não registradas em casa:

git switch -c casa-trabalho-anterior
git add -- nome-do-arquivo
git commit -m "Preserva alterações feitas em casa"
git push -u origin casa-trabalho-anterior

Depois atualize a versão principal:

git switch main
git pull origin main

Não usar git reset --hard, pois pode apagar alterações locais.
